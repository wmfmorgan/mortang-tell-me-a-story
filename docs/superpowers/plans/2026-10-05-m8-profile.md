## Settings

Route `/settings`. A signed-out user still redirects to `/`.

The body is four things. No family name, member list, or family section on the page. The shared header's family menu stays, because that bar is already there.

Parchment page. One column, max width 672, centered.

1. **Name.** Field bound to `profiles.display_name`. Label `Name`.
2. **Email.** Field bound to the stored `profiles.email`. Label `Email`.
3. **Picture.** The same circle rules as the header, at 80×80, plus `Upload picture`. The picker runs in that tap. The preview updates. The file is stored on Save.
4. **Save.** One terracotta button. Label `Save`.

No second button. No confirmation screen. No footer.

### Save

Refuse a blank or whitespace-only name. Do not update the row, do not upload, and do not call `auth.updateUser`. Stay on the page. Do not add `NOT NULL` on `display_name`.

When the name is non-blank:

- Write the trimmed name to `profiles.display_name`.
- If a picture is pending, compress it and upload `{uid}/avatar.jpg`, then set `avatar_path` to that path.
- If the email field differs from the stored `profiles.email`, call `auth.updateUser({ email })` and nothing else for the address. Do not put `email` in the profiles update.
- A blank email field does not call `updateUser` and does not write `profiles.email`. A non-blank name still saves.

`double_confirm_changes` is already true. Confirmation goes to the current address and the new address. `auth.users.email` stays put until both are confirmed. Magic-link delivery stays on the old address until then. The trigger below copies the new address onto `profiles.email` only after that move. After a successful `updateUser`, the field shows the stored `profiles.email` again, because that column has not moved. Save does not navigate.

A failed row update, upload, or `updateUser` shows `Couldn't save your profile. Try again.` A failed upload after a saved name keeps that name and keeps the pending preview.

## Data

Migration `supabase/migrations/20261005000001_profile_avatar.sql` matches the Design Doc. It does not add a column the doc does not name.

```sql
alter table public.profiles
  add column avatar_path text;

alter table public.profiles
  add constraint profiles_avatar_path_own
  check (
    avatar_path is null
    or avatar_path = (id::text || '/avatar.jpg')
  );
```

Private bucket `avatars`. `file_size_limit` 2097152. MIME `image/jpeg` only. One object, `{auth.uid()}/avatar.jpg`. SELECT, INSERT, UPDATE, and DELETE for `authenticated` require `bucket_id = 'avatars'` and `name = auth.uid()::text || '/avatar.jpg'`. Upload upserts. Do not use `story-photos`. No public URL.

Co-member SELECT of `profiles` already returns the row, so it returns `avatar_path`. No other screen paints it. A co-member does not get the file.

Email trigger, same migration. Insert bootstrap stays `handle_new_user()`.

```sql
create or replace function public.sync_profile_email()
returns trigger
language plpgsql
security definer
set search_path = public
as $$
begin
  update public.profiles
    set email = new.email,
        updated_at = now()
    where id = new.id;
  return new;
end;
$$;

create trigger on_auth_user_email_updated
  after update of email on auth.users
  for each row
  when (new.email is distinct from old.email)
  execute function public.sync_profile_email();
```

Reuse `compressStoryPhoto` with `maxEdge: 512` and `quality: 80`. A file the existing decoder cannot read does not upload and uses the SnackBar above. No HEIC package.

`lib/data/profile_session.dart` holds the signed-in name, email, and avatar bytes, and notifies mounted headers after Save. Clear it wherever `FamilySelection` is cleared on a dropped session or a user change. No `shared_preferences`.

Settings loads `listMine()` only so the existing family menu works. Choosing a family remembers that id. The profile is not family-scoped. An open New story form still keeps the family id it loaded.
