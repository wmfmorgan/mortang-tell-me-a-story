## M14.3: DOB visibility and passed away (LOCKED 2026-10-16)

### Data (one new migration after the latest; never edit earlier migrations)
- New enum: `create type dob_visibility as enum ('hidden','year','year_month','full')`.
- `profiles.birth_visibility dob_visibility not null default 'hidden'`. Existing `profiles.birth_date` values stay hidden until the member picks a level. `profiles.birth_date` and `birth_precision` are kept.
- `people.passed_away boolean not null default false`.
- Drop `people.birth_date`, `birth_precision`, `passing_date`, `passing_precision` (and their null-together checks). Nobody enters a DOB or date of passing for anyone else.
### Migration (one transaction, no backup)
- `begin;` create `dob_visibility`; add `profiles.birth_visibility`; add `people.passed_away`.
- `update people set passed_away = true where passing_date is not null;`
- Drop the four `people` date columns and their checks.
- Column revoke on `profiles` (below); replace `person_profile`, `list_unlinked_people`; add `my_profile`, `mark_passed_away`, the `passed_away` guard trigger. `commit;`
- The dropped dates are not kept anywhere. Irreversible.
### Read access (fixes the profiles DOB leak)
- `profiles_select_own_or_comember` exposes the full row to co-members today. Fix: `revoke select (birth_date, birth_precision, birth_visibility) on public.profiles from authenticated, anon`.
- Trimmed read: `person_profile(p_person_id)` (SECURITY DEFINER, `search_path = ''`, `(select auth.uid())`, null uid fails closed, `is_tree_member` check). Returns the birth date trimmed to the coarser of `birth_visibility` and `birth_precision`; null when hidden. Applies to everyone else, owners and co-owners included.
- Own raw read: `my_profile()` (SECURITY DEFINER) or the own-row branch of `person_profile` returns raw `birth_date`, `birth_precision`, `birth_visibility`.
- Settings writes stay on `profiles_update_own`.
- Policy count stays **47** (column revoke is not a policy).
### Passed away
- `mark_passed_away(p_person_id uuid, p_value boolean)`: SECURITY DEFINER, `search_path = ''`. Undo allowed (`p_value = false`).
	- Caller must be owner or co-owner of the target person's **home family** (`people.family_id`) only.
	- Target must be signed in (`user_id is not null`); self is refused.
	- Sets only `passed_away` (and `updated_at`).
	- Errors: `FORBIDDEN:`, `NOT_FOUND:`, `VALIDATION:`. `mapRpcError` stays at 4 prefixes.
	- Execute granted to `authenticated` only.
- Trigger guard on `people` update: a linked user cannot change `passed_away` on their own row through `people_update_member`.
- Unlinked rows: any tree member toggles `passed_away` through Edit person (existing update policy), no confirm dialog.
- Marking someone as passed away changes nothing about their account (membership, sign-in, profile unchanged).
### Invite picker
- `list_unlinked_people` and `create-invite` (`person_id` check) use `not passed_away` in place of `passing_date is null`.
- Pending invites are left as-is when a person is flagged; `accept-invite` does not check the flag.
- Picker rows show the birth year only when visibility is `year` or finer, with no end year. Mugatu rechecks the picker copy.

### M14.3 item 10 — Linked person name follows profile (LOCKED 2026-10-16)
Intake: PRD M14.3 item 10 (Jared) · Decisions (Bill locked 2026-10-16) · live schema read 2026-10-16: the profile name column is `profiles.display_name` (text).
#### Rule
- Once a `people` row has `user_id` set, `people.name` = that user's `profiles.display_name`, in every tree.
- Sync on link and on profile name change.
- No per-tree nickname. Nobody (the member included) renames a linked row directly.
#### Data (one new migration after `20261016140000`; never edit earlier migrations)
- Profile trigger: `AFTER UPDATE OF display_name ON profiles`, SECURITY DEFINER, `search_path = ''`. Sets `set_config('app.name_sync','on',true)`, then `update people set name = new.display_name where user_id = new.id and name is distinct from new.display_name`.
- People guard: `BEFORE INSERT OR UPDATE ON people`, when `new.user_id is not null`:
	- Insert, or update where `user_id` changes (link): overwrite silently, `new.name := profiles.display_name`. Covers invite accept and `ensure_member_person`.
	- Update where `user_id` is unchanged and `new.name` differs from `display_name`, and `app.name_sync` is not `'on'`: raise `FORBIDDEN: linked_person_name_locked` (uses existing FORBIDDEN: prefix; error-prefix gate stays at exactly 4 prefixes; no new mapRpcError prefix).
	- Sync from the profile trigger passes (session flag set).
- Backfill (same migration, idempotent): `update people p set name = pr.display_name from profiles pr where p.user_id = pr.id and p.name is distinct from pr.display_name`. Renames the wfmorgan73 row to 'William F Morgan'.
- Policy count unchanged (triggers are not policies).
#### Client

- Uses existing `FORBIDDEN:` prefix; error-prefix gate stays at exactly 4 prefixes; no new `mapRpcError` prefix for `linked_person_name_locked`.
