## Autosave drafts — data side (LOCKED 2026-10-16)
Source: UXD v1 Handoff "Autosave drafts (LOCKED 2026-10-16)". Bill locked the failure behavior: grey "Not saved" in the Saved slot, text kept, retry at next pause, no popup.
### Blocker found in prod schema
`stories.timeframe_start`, `timeframe_end`, `date_precision` are NOT NULL. A draft created on the first keystroke has no date, so the insert fails today.
### Decision
- One new migration after `20261016140000`: drop NOT NULL on `timeframe_start`, `timeframe_end`, `date_precision`.
- Add CHECK `stories_published_needs_date`: `status <> 'published' OR (timeframe_start IS NOT NULL AND timeframe_end IS NOT NULL AND date_precision IS NOT NULL)`. Publishing still requires a date; violations surface as `VALIDATION: date required` via `mapRpcError` (existing prefix, prefix count stays 4).
- `stories_date_guard` unchanged; it already passes nulls through. Policies unchanged (count stays 47). No new columns, no `updated_at`.
### Client contract
- Client generates the story `id` (uuid v4) at the first keystroke and INSERTs once with `status='draft'`. Every later autosave is an UPDATE by that id. A retried insert that hits a duplicate key is treated as success and switches to UPDATE, so a retry never creates a second draft.
- Autosave fires on a typing pause and on leaving the page; only one request in flight per story, later edits coalesce into the next save.
- Failure: show "Not saved", keep editor state, retry on next pause. Save draft / Publish remain manual and show the real error.
- Second tab or device: last write wins. Single author per story, no merge logic.
- Drafts list and any date-sorted read must tolerate null dates (sort nulls last, show "No date yet" per existing muted ink). Tree and timeline read published only, so they never see null dates.
### Tests
- pgTAP: draft insert with null dates succeeds; publish with null date fails with CHECK; publish with dates succeeds; existing rows unaffected.
- Flutter: first keystroke inserts once; duplicate-key retry becomes update; failed save shows "Not saved" and retries; drafts list renders a null-date draft.

## M14.4 dateless drafts: date guard and late autosave (LOCKED — Gilfoyle architecture fix, 2026-10-17)
Required before PR #40 merges. Both fixes ship inside #40. Migration `20261017000000_story_draft_nullable_date.sql` is not on main or prod yet, so the agent edits that file. No new migration.
### Problem
- `stories_date_guard` sets `date_precision = 'day'` whenever start is not distinct from end. With both null, a dateless draft gets marked as having a day date.
- A dateless publish fails on check `stories_published_needs_date` with the generic `23514` error, not one of the four error prefixes.
- `updateDraft` updates by id only, so an autosave that lands after publish overwrites the published story.
### Fix 1 and 2: append to migration `20261017000000`, after the check constraint
Keep the check constraint `stories_published_needs_date` as a backstop. `create or replace` keeps the trigger binding and grants. It is not security definer, so the allowlist stays 29. The policy count stays 47. `VALIDATION:` is an existing prefix, so there are still 4 prefixes and `mapRpcError` does not change.
```sql
create or replace function public.stories_date_guard()
 returns trigger
 language plpgsql
 set search_path to ''
as $function$
begin
  -- Old inserts stored a single day as a null end. Fill that shape only.
  if new.timeframe_end is null then
    new.timeframe_end := new.timeframe_start;
  end if;
  -- Default to day only when a date exists. Dateless drafts keep null precision.
  if new.date_precision is null
     and new.timeframe_start is not null
     and new.timeframe_start is not distinct from new.timeframe_end then
    new.date_precision := 'day';
  end if;

  if new.status = 'published'
     and (new.timeframe_start is null or new.date_precision is null) then
    raise exception 'VALIDATION: date required';
  end if;

  if tg_op = 'INSERT'
     and new.date_precision = 'decade'::public.story_date_precision then
    raise exception 'VALIDATION: year required';
  end if;

  if tg_op = 'UPDATE'
     and new.date_precision = 'decade'::public.story_date_precision
     and (
       old.date_precision is distinct from 'decade'::public.story_date_precision
       or new.timeframe_start is distinct from old.timeframe_start
       or new.timeframe_end is distinct from old.timeframe_end
     ) then
    raise exception 'VALIDATION: year required';
  end if;

  return new;
end;
$function$;
```
The decade checks are copied unchanged from the prod body read on 2026-10-17.
### Fix 3: new `autosaveDraft` in `stories_api.dart` (revised 2026-10-17, Big Head's conflict)
`updateDraft` stays unchanged, because edit mode's Save changes on a published story goes through it (2026-10-11 lock). Add `autosaveDraft(...)`, used only by autosave and the save on leave. Publish and Save changes keep using `updateDraft`.
- `autosaveDraft` filters `id = :id AND status = 'draft'` (`.eq('id', id).eq('status', 'draft')`) and selects the returned rows. When no row matches, it skips the `story_people` replace.
- `autosaveDraft` and `updateDraft` share one private write helper (story update plus `story_people` replace). The `status = 'draft'` filter is a parameter and is the only difference. No copied update body.
- `_persistDraft` clears `_autosaveDirty` either way (Dinesh).
- `autosaveDraft` returns `bool`: `true` when a row was written, `false` when zero rows matched. `false` means the story is no longer a draft: no error, no retry, the status label goes blank (no "Saved", no "Not saved", per Mugatu), and the editor stops autosaving that story.
- No RLS or database change for this fix.
### Tests
- pgTAP: insert a draft with null `timeframe_start`, null `timeframe_end` and null `date_precision`. All three stay null.
- pgTAP: a draft with a start date and no precision still gets `day`.
- pgTAP: publishing a dateless draft (update and insert) throws `VALIDATION: date required`, not `23514`.
- pgTAP: the existing `VALIDATION: year required` decade tests still pass.
- pgTAP: the policy count is 47 and the definer allowlist is 29.
- Flutter: publish a draft, then fire a pending `autosaveDraft` with new text. The published row's text and `story_people` are unchanged, `autosaveDraft` returns `false`, no error is shown, and the status label is blank. Also: Save changes on a published story through `updateDraft` still writes.
